- 2026-05-28 — Item 4 (chat persistence + chats store) — DONE.
  - Design choice: a dedicated `chats` TABLE, not a `kind='chat'` artifact. A chat is not a renderable artifact — it's a durable handle mapping a workspace → an opencode session id + a human title, ordered by recency for the sidebar history list (§10). opencode sessions are otherwise ephemeral with no durable list; this table IS that list. Messages stay in opencode and are reloaded by session id on reopen, so the table stores the mapping, not the transcript. The artifact columns (view_spec/kind/parent_*) don't fit a chat handle, so a table is cleaner.
  - `supabase/migrations/0002_chats.sql`: additive idempotent `chats` table (`id`, `workspace_id` FK→workspaces ON DELETE CASCADE, `user_id`/`org_id` with the same `(user_id is null) <> (org_id is null)` one-owner check used by workspaces, `session_id text not null`, `title` default 'New chat', `created_at`/`updated_at`/`last_message_at`), three indexes (`(workspace_id, last_message_at desc)`, `(user_id, last_message_at desc)`, `(session_id)`), and 4 RLS policies (select/insert/update/delete) mirroring workspaces/artifacts via `is_org_member`/`has_org_role`. Every object guarded (`create table/index if not exists`, `drop policy if exists`→`create policy`). Folded the identical block into `supabase/schema.sql` (after the artifacts.workspace_id index, so the workspaces/orgs FK + helper deps already exist) so a fresh paste is complete.
  - Parse-check: `pglast` 7.13 (libpg_query) — migration parses (13 statements), schema.sql parses (135), and schema.sql + 0002 concatenated parses (148), confirming the migration is re-pasteable on top. NOT applied to the live DB (no local pg server on the VM; same as items 1-2).
  - Store layer split so it's unit-testable: `lib/chats-store.ts` holds the pure/injectable core (NO `server-only`/`@/` imports so jiti can load it) — `createChatWith`/`listChatsWith`/`getChatWith`/`touchChatWith` against a minimal `ChatDbClient` structural type, plus pure `deriveChatTitle` (collapses whitespace, strips the composer's `[active-network]` preamble, truncates at 80). `lib/chats.ts` re-exports the core types + `deriveChatTitle` and adds the RLS-checked `createClient()`-backed wrappers (`createChat`/`listChats`/`getChat`/`touchChat`) the routes call.
  - Routes: `app/api/chats/route.ts` — `GET ?workspace_id=` lists a workspace's chats (recency desc), `POST {workspace_id, session_id, first_message?, title?, org_id?}` creates one. `app/api/chats/[id]/route.ts` — `GET` returns one chat (its session id is the reopen handle; client reloads messages via the existing `GET /api/opencode/session/[session_id]/message`), `PATCH` bumps recency. `/api/chats` gated in `proxy.ts`.
  - Front-end wiring (`app/app/page.tsx`): added `chatIdRef`; on a successful prompt POST, `persistChat(session, rawMessage)` POSTs `/api/chats` on the first message (storing workspace_id=null until the gallery/wizard items 9-10 bind a workspace — the column is nullable by design) and PATCHes recency on later ones. Best-effort: a persistence hiccup never breaks the conversation (which lives in opencode). The sidebar that LISTS/OPENS chats from this store is item 5 — this item delivers the store + persistence + reopen handle.
  - Verification: `npx tsc --noEmit` exit 0; `npm run test:unit` 23/23 pass (13 prior + 10 new in `tests/unit/chats-store.test.mjs` covering deriveChatTitle, create persists with derived title, org-owned nulls user_id, list recency-desc + workspace-scoped, reopen via getChat returns session id, getChat null for unknown, touch floats a chat up the list). Did NOT run a browser / `next build`/`dev` / touch :3000 per guardrails. Visual review of the eventual sidebar UI is deferred to item 5; nothing visual changed in this item beyond the silent persist call.
